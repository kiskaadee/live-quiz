Direct audit of `transcript_full.jsonl` separates established user commitments from unapproved assistant recommendations:

### A. Verified Invariants (`USER_EXPLICIT` Provenance — Do Not Re-Ask)
- **Steps `820`, `825`, `827` (Handoff v2 & Baseline Corrections):**
  - **`A`:** Immutable pair $A = (Q, R)$; modification of either member requires registering a new flat `assessment_id` issued by `learningctl`; `assessment_version` and version lineage eliminated; M:N Competency↔Objective and Assessment↔Objective links (Competency↔Assessment derived); Tutor owns pedagogical reassessment decisions, performs `AVAILABLE` artifact pre-flight prior to offering reassessment, and requires explicit learner consent before new registration or reassessment.
  - **`B1`:** Registered $Q$ and $R$ embed `assessment_id`; $R$ carries `expected_questionnaire_hash`; $H_q = \operatorname{SHA256}(\operatorname{JCS}(Q))$ over the entire validated public questionnaire (including `assessment_id` when present); `expected_sha256` ([ADR-0007](../docs/decisions/0007-atomic-json-export-contract.md)) remains separate; standalone execution (`live-quiz start --questionnaire <path>`) is supported without `assessment_id` or `workspace_id`.
  - **`C1` & Partial `C2`:** `live-quiz` commits a complete, self-contained questionnaire snapshot and initial execution metadata (`attempt_id`, optional `assessment_id`, $H_q$, optional `workspace_id`, `time_limit_ns`) to the attempt journal before learner access; recovery uses only the journal snapshot. No historical journal migration for missing snapshots is needed (no prior deployment).
  - **Foundational `D` & `E` Invariants:**
    - One OS-wide persistent encrypted Learning Registry (candidate: `SQLCipher`); workspaces are logical provenance resolved via nearest-ancestor `.learning-workspace` marker (`workspace_id`), rejecting Git root as workspace boundary.
    - Separate host provisioning vs. `learningctl init` (`init` never silently recreates a missing global DB).
    - `learningctl` (narrow domain CLI; black-box `learningctl.md`/`--help` contract) $\to$ private typed UDS IPC $\to$ `learning-registryd` (`learning-registry` OS account, systemd socket activation `Accept=no`, serialized requests).
    - Non-TPM default host key protection (stored outside workspaces and separate from DB backups); `learning-registryd` owns Online Backup API encrypted-to-encrypted snapshots on schedule and before disruptive operations.
    - Registration lifecycle (`REGISTERING` $\to$ `AVAILABLE` / `ABORTED`; only `AVAILABLE` is discoverable; allocated `assessment_id` never reused; registration failure $\neq$ attempt recovery).
    - Temporary public-only questionnaire materialization outside workspace, deleted idempotently via `learningctl` after durable engine snapshot commit.
    - Read-only `learningctl status` (`--json`, `--all`) run once at Tutor initialization (no polling); `learningctl` discovers candidate journals while `live-quiz` is sole authority for active vs. recoverable state without exposing private SQLite tables.
    - Per-command `schema_version` in `learningctl --json` outputs (additive changes increment compatibly, breaking changes increment incompatibly, ignore unknown fields, reject unsupported breaking versions; exact `major.minor` string syntax remains unverified per step `827`).
    - In registry-managed workflows, `attempt.json` is an intermediate artifact staged in a persistent non-workspace staging area (no TTL deletion) until the complete learning interaction (`attempt` + `evaluation` + `Tutor observations`) is committed in one atomic registry transaction (`CONSOLIDATED`) with an idempotent receipt. Standalone `attempt.json` exports remain untouched user files.
    - Interaction states: `PENDING_DEBRIEF`, `DEFERRED`, `PENDING_CONSOLIDATION`, `CONSOLIDATED`, `ABANDONED`. Abandonment separates **append-only historical events** from **reversible current disposition** (`ABANDONED` $\to$ `DEFERRED` or new attempt on explicit learner request; hidden from default `status` and `--all`). Bounded debrief (1 consolidated report + ~1–3 follow-up turns) is a **facilitation guideline**, not a hard technical limit; interrupted debriefs preserve lightweight structured progress rather than full chat transcripts.
- **Step `829` (`B2.1` Accepted):** $H_q$ is computed over the original parsed JSON representation after strict validation (`extra="forbid"`, `strict=True`), never Pydantic's `model_dump()`.
- **Step `845` (`B2.2` Accepted):** Project-specific strict RFC 8785 JCS-compatible input profile scoped exclusively to `questionnaire.json` (UTF-8 without BOM, no lone surrogates or Unicode noncharacters, no Unicode normalization such as NFC/NFD performed with decoded code points preserved exactly and already-normalized NFC/NFD input accepted, no duplicate keys after unescaping, no non-finite constants, no float/exponent tokens at `parse_float` boundary, integers in $[-(2^{53}-1), +(2^{53}-1)]$; not transferred to `attempt.json`/`evaluation.json`).
- **Step `847` (`B2.3` Accepted):** 3-layer separation (strict Layer 1 parser $\to$ full RFC 8785 Layer 2 canonicalizer on Layer 1 structure $\to$ SHA-256), independent component implementations using established RFC 8785 libraries (no hand-written JCS, no shared first-party runtime package), verified by a mandatory raw-byte shared CI conformance suite.
- **Step `849` (`B2.4` Decomposition & Framing Constraints):** Decomposed `B2.4` into five subdecisions (`B2.4.1`–`B2.4.5`) with fixed constraints (`schema_version` inside $H_q$; changing it creates a new `assessment_id` without lineage; no in-place pair migration; cosmetic/internal changes do not require a new version).
